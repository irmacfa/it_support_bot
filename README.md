# ربات پشتیبانی آی‌تی (جستجوی شماره فروشگاه)

## ساختار پروژه
```
it_support_bot/
├── app/
│   ├── config.py       تنظیمات (توکن، رمز، مسیر فایل‌ها، override ستون‌ها)
│   ├── data_store.py   خوندن اکسل و جستجو + موتور diff/merge فایل شارژ
│   ├── info_store.py   اطلاعات فروشگاه‌ها (چارت سازمانی، نام مدیران) به‌صورت چندشیتی
│   ├── main.py         پنل وب آپلود (FastAPI)
│   └── bale_bot.py     ربات بله (polling)
├── data/
│   ├── stores.xlsx        فایل اکسل فروشگاه‌ها (خودکار ساخته میشه)
│   ├── stores/            فایل‌های آپلودشده‌ی فعال (جایگزین stores.xlsx می‌شن)
│   ├── stores_backup/     نسخه‌های پشتیبان خودکار (۳ نسخه‌ی آخر، قابل بازگردانی)
│   ├── store_schema.json  گزارش بررسی فایل‌ها (چی شناسایی شد، چی ایندکس نشد)
│   ├── store_snapshot.json وضعیت اعمال‌شده (مبنای تشخیص تغییر بعدی)
│   ├── info_stores.xlsx   اطلاعات فروشگاه‌ها (چند شیت)
│   ├── info_backup/       نسخه‌های پشتیبان اطلاعات (۳ نسخه‌ی آخر)
│   ├── info_schema.json   گزارش بررسی فایل اطلاعات
│   ├── info_snapshot.json وضعیت اعمال‌شده‌ی اطلاعات
│   └── upload_staging/    آپلودهای تأییدنشده (تا ۶ ساعت نگه داشته می‌شن)
├── templates/
│   └── upload.html      صفحه‌ی آپلود
├── requirements.txt
└── .env.example
```

## نصب

```bash
cd it_support_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env   # توکن ربات و رمز پنل رو بذار
```

## اعمال تغییرات (چطور فایل جدید داده‌ی قبلی رو دست نمی‌زنه)

آپلود دو مرحله‌ایه: **اول بررسی، بعد اعمال.**

1. فایل رو انتخاب می‌کنی و یکی از این حالت‌ها رو انتخاب می‌کنی:
   - **🤖 خودکار تشخیص بده** (پیش‌فرض): سیستم خودش فایل جدید رو با داده‌ی فعلی مقایسه می‌کنه. اگر **۹۰٪ یا بیشتر** از کدهای فعلی داخل فایل جدید باشه، فایل رو «عکس کامل» حساب می‌کنه و **جایگزینی** رو پیشنهاد می‌ده؛ اگر کمتر باشه، فایل رو «فایل تغییرات» حساب می‌کنه و **ادغام** رو پیشنهاد می‌ده. نتیجه همراه دلیلش (مثلاً «۱۰۰٪ از کدهای فعلی (۷۵۵ از ۷۵۵) داخل فایل جدید هست») بالای پیش‌نمایش نشون داده می‌شه و چیزی بدون تأیید تو اجرا نمی‌شه.
   - **فقط تغییرات رو اعمال کن**: رکوردهای جدید اضافه می‌شن، رکوردهای تغییرکرده جایگزین می‌شن و بقیه دست‌نخورده می‌مونن.
   - **جایگزینی کامل**: کل داده‌ی فعلی پاک می‌شه و فقط همین فایل مبنا می‌شه.
   - گزینه‌ی «کدهایی که توی فایل جدید نیستن هم حذف بشن» پیش‌فرض خاموشه.

   حالت خودکار فقط **پیشنهاد** است؛ اگر تشخیص سیستم را پسندیدی با «اعمال تغییرات» بزن، و اگر نه، برگرد و حالت دستی را انتخاب کن. آستانه‌ی ۹۰٪ در `AUTO_REPLACE_COVERAGE` داخل `app/data_store.py` قابل تغییر است.
2. قبل از اعمال، جدول تغییرات رو می‌بینی: هر کد جدید، هر کد تغییرکرده به‌همراه **قدیم ← جدید** هر فیلد، و کدهایی که توی فایل نیستن.
3. با «اعمال تغییرات» اعمال می‌شه، یا با «انصراف» همه‌چیز دور ریخته می‌شه.

تشخیص تغییر بر اساس محتوای واقعی رکورد انجام می‌شه (شماره‌ی ردیف و اسم فایل مهم نیستن)، پس اگه فایل رو جابه‌جا کنی یا دوباره آپلود کنی، هیچ تغییری تشخیص داده نمی‌شه و دیتا دست‌نخورده می‌مونه.

وضعیت اعمال‌شده توی `data/store_snapshot.json` ذخیره می‌شه، برای همین بعد از ری‌استارت سرویس هم رکوردهایی که توی فایل جدید نبودن از بین نمی‌رن.

## فرمت فایل شارژ

**هیچ قالب اجباری‌ای وجود نداره.** هر فایلی که آپلود کنی (`.xlsx` / `.xlsm` / `.csv`) خودش بررسی میشه:

- **همه‌ی شیت‌ها** خونده میشن، نه فقط شیت اول.
- سطر هدر خودکار پیدا میشه (لازم نیست ردیف اول باشه).
- **همه‌ی ستون‌ها** نگه داشته میشن؛ ستون‌های بی‌نامِ دارای داده هم با اسم ستون اکسل (مثل `ستون W`) می‌مونن.
- ستون «کد فروشگاه»، «شماره سیم‌کارت»، «اپراتور» و «محل نصب» خودکار از روی اسم ستون و محتوای سلول‌ها شناسایی میشن.
  اگه فایلتون اسم ستون متفاوتی داره، لازم نیست چیزی عوض کنید — ولی میشه با `SHEETS` توی `app/config.py` صریحاً مشخص کرد.
- اگه کد فروشگاه داخل متن نوشته شده باشه هم پیدا میشه:
  `جمع آوری از 1120` ، `نزد کارشناس (جمع آوری شده از 1171)` ، `فروشگاه 3024` ، `1249-1250` ، `مهدی‌زاده(جمع آوری از 1172)`
- ردیف‌هایی که هیچ کدی نداشته باشن بی‌صدا حذف نمی‌شن؛ توی گزارش صفحه‌ی آپلود با «ردیف بدون کد» و «شیت ایندکس نشد» گزارش میشن.
- اگه فایلی آپلود کنی که هیچ کدی توش پیدا نشه، آپلود رد میشه و **فایل‌های قبلی سر جاشون می‌مونن**.
- قبل از هر اعمال، از فایل‌های قبلی نسخه‌ی پشتیبان گرفته میشه (۳ نسخه‌ی آخر) و از همون صفحه قابل بازگردانیه.
- اگه فایل اکسل رو اشتباهی توی فرم برنامه‌ی شیفت بدی، خودکار به بخش فروشگاه‌ها هدایت می‌شه.
- شیت‌هایی که ربطی به فروشگاه ندارن (مثل «مبلمان») معمولاً خودکار تشخیص داده و ایندکس نمی‌شن.

فرمت‌های مجاز: `xlsx`, `xlsm`, `csv` (فایل `xls` قدیمی نیست؛ با اکسل به `xlsx` ذخیره کنید).

## فایل اطلاعات فروشگاه‌ها (چارت سازمانی و نام مدیران)

بخش «📋 فایل اطلاعات فروشگاه‌ها» از `data/info_stores.xlsx` می‌خونه و هر دو جریان بالا رو دقیقاً مثل فایل شارژ داره: **اول پیش‌نمایش، بعد اعمال**، با پشتیبان‌گیری خودکار و بازگردانی.

برخلاف فایل شارژ، لازم نیست اسم شیت یا ستون از پیش مشخص باشه:

- **همه‌ی شیت‌ها** خونده می‌شن و شیتی که ستون کد فروشگاه نداشته باشه بی‌صدا رد نمی‌شه — توی گزارش با «شیت ایندکس نشد» و دلیلش اعلام می‌شه.
- سطر هدر خودکار پیدا می‌شه (لازم نیست ردیف اول باشه) و ستون کد فروشگاه هم با اسم ستون و هم با محتوای سلول‌ها شناسایی می‌شه.
- یک کد می‌تونه توی چند شیت بیاد؛ نتیجه به‌صورت چند رکورد برای همون کد نگه داشته می‌شه و ربات همه‌شون رو با عنوان شیت نشون می‌ده.
- وضعیت اعمال‌شده توی `data/info_snapshot.json` ذخیره می‌شه تا بعد از ری‌استارت سرویس هم رکوردهای ادغامی از بین نرن.
- اگه فایلی آپلود کنی که هیچ کد فروشگاهی توش نباشه، آپلود رد می‌شه و فایل قبلی سر جاش می‌مونه.
- اعداد اعشاری قبل از مقایسه گِرد می‌شن، پس خطای نمایش اکسل (مثل `35.688917000000004`) به‌عنوان «تغییر» الکی گزارش نمی‌شه.

همون رفتار برای فایل شارژ هم یکسانه؛ فقط اگه نحوه‌ی نرمال‌سازی مقادیر عوض بشه، `SNAPSHOT_VERSION` توی `app/data_store.py` باید بالا بره تا snapshot قدیمی دور ریخته و از خود فایل‌ها بازسازی بشه.

### شیت «کارشناس انفورماتیک»

شیتی با همین نام توی `data/info_stores.xlsx` هست که دو ستون داره: `کد فروشگاه` و `کارشناس انفورماتیک`. ربات خودکار اون رو مثل بقیه‌ی شیت‌ها ایندکس می‌کنه و به‌عنوان یک بخش جدا توی نتیجه نشون می‌ده (عنوانش رو مثل بقیه از پنل می‌شه تغییر داد یا مخفی کرد).

داده‌ی این شیت از دو منبع مختلف جمع شده:

- **پشتیبان منطقه** (تهران، البرز، سمنان، مرکزی، جنوب شرق، کافه، فرانچایز): از فایل «پشتیبان فروشگاه های منطقه تهران و کرمان - مرداد405.xlsx».
- **انفورماتیک** (کرمانشاه، ایلام، لرستان، همدان): از جدول `store_registry` ستون `it_support` توی دیتابیس پروژه‌ی قدیمی `bot_project/bot.db`.

این دو منبع هیچ اشتراکی ندارن (مناطق متفاوت، پرسنلی متفاوت). ۴۸۹ فروشگاه کارشناس دارن و ۲۲۴ فروشگاه (گیلان، مازندران، خراسان و چند مورد تهران) هنوز خالی‌ان. فروشگاهی که کارشناس نداره، توی نتیجه‌ی ربات اصلاً بخش «کارشناس انفورماتیک» نداره، ولی توی فهرست پنل با «تعیین نشده است» مشخص می‌شه تا گم نشه.

برای پر کردن خالی‌ها، فهرستشون با منطقه و شهر توی `bot_project/_recovered/کارشناس-نیازمند-تکمیل.xlsx` هست؛ یا مستقیم همون شیت رو توی اکسل پر کن و از بخش آپلود اطلاعات فروشگاه‌ها بفرست.

⚠️ **مهم:** برای اضافه‌کردن شیت به فایل اطلاعات، از `openpyxl` استفاده نکن — روی این فایل بخشی از رشته‌ها را پاک می‌کنه. `scripts/inject_sheet.py` و `app/xlsx_sheet.py` شیت رو در سطح zip اضافه می‌کنن و بقیه‌ی اجزای فایل رو byte-for-byte دست‌نخورده نگه می‌دارن.

### حفظ ساختار فایل هنگام آپلود چارت سازمانی

هر چارت سازمانی جدیدی که آپلود می‌شه، کل فایل رو جایگزین می‌کرد و شیت‌هایی که فقط توی فایل ما بودن (مثل `کارشناس انفورماتیک` و `فروشگاههای بسته شده`) از بین می‌رفتن. حالا `carry_over_info_sheets()` توی `app/main.py` قبل از پیش‌نمایش و قبل از اعمال، شیت‌های موجودِ جاافتاده رو از فایل فعلی به فایل جدید منتقل می‌کنه و اسمشون رو توی پیام نتیجه اعلام می‌کنه.

دو محافظت مهم:

- **فایل بی‌ربط نباید قبول بشه:** اگه فایل آپلودی حتی یک شیت مشترک با فایل فعلی نداشته باشه (مثلاً فایل اشتباهی)، اصلاً چیزی منتقل نمی‌شه تا بررسی‌های معمولی ردش کنن. بدون این محافظ، یه فایل بی‌کد شیت‌های فعلی رو graft می‌کرد و به‌عنوان فایل معتبر قبول می‌شد.
- **فقط xlsx:** انتقال شیت با دستکاری مستقیم zip انجام می‌شه، پس برای csv ممکن نیست و صریحاً توی لاگ هشدار داده می‌شه (شیت‌های فعلی از بین می‌رن).

نرمال‌سازی مقادیر هم اینجا مهمه: فایل سازمانی مختصات‌ها رو ناهمگون ذخیره کرده (بعضی `35.662250` به‌صورت متن، بعضی `35.688917000000004` به‌صورت عدد). اگه این‌ها یکی نشن، آپلود مجددِ سالمِ همون فایل از اکسل «۸۱ کد تغییرکرده» گزارش می‌کرد. `trim_float_noise()` توی `app/xlsx_sheet.py` و `_info_value()` توی `app/info_store.py` این نویز رو حذف می‌کنن، بدون دست‌زدن به شماره‌هایی مثل `09123456789`. چون معنی ایندکس عوض شده، `INFO_INDEX_VERSION` توی `app/info_store.py` باید بالا بره تا اسنپ‌شات‌های قدیمی نادیده گرفته بشن.

### فهرست یکپارچه‌ی فروشگاه‌ها در پنل

توی صفحه‌ی «نمایش کامل دیتا» یه زبانه‌ی «فهرست کامل فروشگاه‌ها» اضافه شده که همه‌ی کدهای ایندکس‌شده (۹۱۷ کد) رو در یک جدول می‌ده: هر کد یک سطر، و ستون‌ها از همه‌ی شیت‌ها ادغام شدن.

- ستون‌های هم‌نامِ چند شیت روی هم جمع نمی‌شن؛ اولین شیتی که مقدار داشته باشه برنده‌ست (ترتیب شیت‌ها = ترتیب فایل). برای اینکه ستون‌های باقی‌مونده قابل تشخیص باشن، برچسبشون با `· نام شیت` جدا می‌شه.
- ستون `کارشناس انفورماتیک` همیشه نمایش داده می‌شه و فروشگاه بدون کارشناس با «تعیین نشده است» و رنگ هشدار مشخصه.
- با دکمه‌ی «انتخاب ستون‌ها» می‌شه ستون‌های دلخواه رو انتخاب کرد؛ انتخاب توی `data/fields_config.json` زیر کلید `store_list` ذخیره می‌شه. `کد فروشگاه` و `کارشناس انفورماتیک` قابل حذف نیستن.
- دکمه‌ی «فقط تعیین نشده است» فروشگاه‌های بی‌کارشناس رو فیلتر می‌کنه تا راحت پیدا بشن.

### ویرایش گروهی کارشناس انفورماتیک

توی همون زبانه، دکمه‌ی «✏️ ویرایش گروهی کارشناس» یه کار رو دسته‌ای انجام می‌ده: یه محدوده‌ی کد فروشگاه می‌دی و یه کارشناس، و همه‌ی فروشگاه‌های اون محدوده باهاش تخصیص پیدا می‌کنن.

- محدوده با «از کد» و «تا کد» مشخص می‌شه. اگه «تا کد» خالی بمونه، «از کد» به‌عنوان **پیشوند** تفسیر می‌شه: `3500` یعنی همه‌ی کدهای ۳۵۰۰ تا ۳۵۹۹، و `20` یعنی ۲۰۰۰ تا ۲۰۹۹. برای بازه‌ی دلخواه (مثلاً ۲۰۰۰ تا ۲۹۹۹) هر دو کادر رو پر کن.
- نام کارشناس از فهرست کسانی که الان توی داده هستن پیشنهاد می‌شه، ولی هر اسم دلخواهی رو می‌شه دستی تایپ کرد.
- «فقط فروشگاه‌های بدون کارشناس» (پیش‌فرض روشن) تخصیص‌های موجود رو دست نمی‌زنه. اگه خاموشش کنی، بازنویسی هم انجام می‌شه و پیش‌نمایش تعداد بازنویسی‌ها رو با کادر قرمز نشون می‌ده.
- همیشه «پیش‌نمایش» زده می‌شه قبل از «اعمال»: تعداد فروشگاه‌های درگیر و چند نمونه کد نشون داده می‌شه.
- قبل از اعمال، بکاپ گرفته می‌شه؛ اگه نوشتن فایل شکست بخوره، نسخه‌ی قبلی خودکار برمی‌گرده.
- کدهایی که توی شیت کارشناس ردیف ندارن ولی توی ایندکس هستن، به‌صورت سطر جدید اضافه می‌شن.
- **فروشگاه‌های بسته استثنا هستن:** کدهای شیت `فروشگاههای بسته شده` نه تخصیص می‌گیرن، نه از ویرایش گروهی ساخته می‌شن و نه توی تب «لیست کارشناسان» نمایش داده می‌شن. تابع `closed_codes()` این کدها رو از همون شیت می‌خونه و `clear_closed_experts()` تخصیص‌های قبلیِ فروشگاه‌های بسته رو پاک می‌کنه. توی تب «فهرست کامل فروشگاه‌ها» بسته‌ها همچنان دیده می‌شن، چون اون تب مرجع کلیه.
- سازوکار فنی: `bulk_assign_expert()` و `preview_expert_bulk()` توی `app/info_store.py` و routeهای `POST /api/expert/bulk`، `POST /api/expert/store` و `POST /api/expert/rename` در `app/main.py`. نوشتن فایل با `replace_sheet()` توی `app/xlsx_sheet.py` انجام می‌شه که فقط همون یک part از xlsx رو بازنویسی می‌کنه؛ بقیه‌ی شیت‌ها byte-for-byte دست‌نخورده می‌مونن. **از `openpyxl` برای نوشتن فایل اصلی استفاده نکنید** — رشته‌ها را پاک می‌کند.


### کارشناس منطقه و اطلاع‌رسانی گروه

پایین تب «لیست کارشناسان» یک بخش «🗺 کارشناس انفورماتیک هر منطقه» هست که برای
هر منطقه یک dropdown می‌گذاری تا کارشناسش انتخاب شود. این نگاشت در
`data/region_experts.json` نگه‌داری می‌شود (ماژول `app/region_experts.py`) و
مستقل از شیت اکسل است، چون تصمیم سازمانی است نه تخصیص فروشگاهی.

دو دکمه پیش‌نمایش پیام می‌سازند و چیزی نمی‌فرستند:

- `POST /api/announce/preview` با `{"kind": "regions"}` → جدول «منطقه → کارشناس»
  به‌همراه فهرست مناطقی که هنوز تعیین نشده‌اند.
- `POST /api/announce/preview` با `{"kind": "unassigned"}` → فروشگاه‌های **فعال**
  بدون کارشناس، دسته‌بندی‌شده بر اساس منطقه.

ارسال با `POST /api/announce/send` انجام می‌شود و متن را **سمت سرور** می‌سازد
(نه از کلاینت می‌گیرد) تا پیام هیچ‌وقت با داده‌ی کهنه نرود. مقصد گروهی است که
عنوانش `ANNOUNCE_GROUP_TITLE` در `app/main.py` باشد. متن‌های بلندتر از ۴۰۹۶
کاراکتر تکه‌تکه فرستاده می‌شوند.

### ذخیره‌ی گروهی کارشناس فروشگاه‌ها

انتخاب کارشناس در dropdownهای تب «لیست کارشناسان» دیگر فوراً ذخیره و صفحه را
refresش نمی‌کند؛ فقط ردیف علامت‌دار (`.dirty`) می‌شود و شمارنده بالای دکمه
به‌روز می‌شود. دکمه‌ی «💾 ذخیره‌ی گروهی» همه‌ی انتخاب‌ها را در **یک** درخواست
به `POST /api/expert/bulk-store` می‌فرستد و `set_store_experts_bulk()` توی
`app/info_store.py` همه را با یک بار بازنویسی شیت ذخیره می‌کند (به‌جای یک
درخواست و یک بازنویسی به‌ازای هر فروشگاه). فروشگاه بسته بی‌صدا رد می‌شود و در
`skipped` برمی‌گردد.

### تب «لیست کارشناسان»

توی صفحه‌ی `/data` یک تب به اسم «لیست کارشناسان» هست که فروشگاه‌ها رو بر اساس کارشناس گروه‌بندی می‌کنه. هر گروه بازشوئه و داخلش جدول کد فروشگاه، نام فروشگاه، منطقه و نام کارشناس رو نشون می‌ده. دوتا کار می‌شه کرد:

- **تغییر کارشناس یک فروشگاه** با dropdown هر ردیف (`POST /api/expert/store`). اگه فروشگاه توی شیت کارشناس ردیف نداشته باشه، سطر تازه ساخته می‌شه. گزینه‌ی «تعیین نشده است» تخصیص رو خالی می‌کنه. فروشگاه بسته پذیرفته نمی‌شه.
- **تغییر نام یک کارشناس برای همه‌ی فروشگاه‌هاش** (`POST /api/expert/rename`)، با تأیید تعداد فروشگاه‌های درگیر.

هر دو عملیات قبل از نوشتن بکاپ می‌گیرن و در صورت خطا فایل برمی‌گرده. توابع بک‌اند: `get_expert_groups()`، `set_store_expert()` و `rename_expert()` توی `app/info_store.py`. فروشگاه‌های بسته در این تب اصلاً نمی‌آید.

### تغییر عنوان شیت‌ها و ستون‌ها در نتیجه

توی دکمه‌ی «مشاهده فیلدها»ی کارت اطلاعات فروشگاه‌ها، برای هر شیت دو چیز قابل تنظیمه:

- **عنوان شیت**: همون تیتری که اول هر بخش توی نتیجه‌ی ربات میاد. می‌شه اسم دلخواه نوشت (مثلاً `Data` → `مشخصات فروشگاه`) یا با خاموش‌کردن تیک، خودِ تیتر رو حذف کرد — داده‌ها همچنان نمایش داده می‌شن.
- **ستون‌های شیت**: تغییر نام، تغییر ترتیب (کشیدن) و تیک‌زدن برای حذف از نتیجه — دقیقاً مثل فایل شارژ.

اگه همه‌ی ستون‌های یک شیت از نتیجه حذف بشن، کل اون بخش دیگه نمایش داده نمی‌شه (به‌جای تیتر خالی). تنظیمات عنوان‌ها توی `data/fields_config.json` زیر کلید `info_sheets` ذخیره می‌شه.

کافیه عنوان جدید رو تایپ کنی و «ذخیره تنظیمات» رو بزنی — نیازی به زدن ✅ یا Enter نیست (با کلیک بیرون از فیلد هم همون لحظه ثبت می‌شه). اسم فعلی هر شیت توی زبانه‌ی مودال به‌شکل «عنوان جدید (عنوان اصلی شیت)» نمایش داده می‌شه تا از وضعیت مطمئن بشی.

## اجرا (برای تست دستی)

```bash
# پنل آپلود
uvicorn app.main:app --host 0.0.0.0 --port 8000

# ربات (توی یه ترمینال جدا)
python -m app.bale_bot
```

پنل آپلود از طریق `http://<IP-سرور>:8000` در دسترسه.

## اجرای دائمی روی سرور (systemd)

دو تا سرویس جدا بساز چون پنل وب و ربات دو پروسه‌ی مستقلن.

**`/etc/systemd/system/it-support-panel.service`**
```ini
[Unit]
Description=IT Support Bot - Upload Panel
After=network.target

[Service]
User=YOUR_USER
WorkingDirectory=/path/to/it_support_bot
ExecStart=/path/to/it_support_bot/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

**`/etc/systemd/system/it-support-bot.service`**
```ini
[Unit]
Description=IT Support Bale Bot
After=network.target

[Service]
User=YOUR_USER
WorkingDirectory=/path/to/it_support_bot
ExecStart=/path/to/it_support_bot/venv/bin/python -m app.bale_bot
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now it-support-panel it-support-bot
sudo journalctl -u it-support-bot -f   # مشاهده لاگ ربات
```

## نکات امنیتی

- پنل آپلود فقط با رمز عبور محافظت میشه؛ پیشنهاد میشه پشت یه ریورس‌پروکسی (nginx) با HTTPS بذاریش، چون الان رمز به‌صورت متن ساده روی HTTP رد و بدل میشه.
- اگه سرور دامنه/SSL داره، می‌تونی به‌راحتی این پنل رو پشت nginx با گواهی Let's Encrypt بذاری.
- فایل `.env` رو هرگز توی گیت پابلیک قرار نده.

## نکات فنی

- کد فروشگاه قبل از جستجو نرمالایز میشه (حذف فاصله، تبدیل اعداد فارسی/عربی به انگلیسی، حذف صفرهای اضافه انتهایی مثل `1033.0`)، پس کاربر می‌تونه هم `101` بفرسته هم `۱۰۱`.
- هر بار فایل جدید آپلود بشه، کل کش توی حافظه بازسازی میشه — نیازی به ری‌استارت سرویس نیست. دکمه‌ی «بازخوانی فایل‌های فعلی» هم همین کار رو می‌کنه.
- اگه فایل اکسل خیلی بزرگ باشه (چند ده‌هزار ردیف)، خوندنش چند ثانیه طول می‌کشه ولی چون فقط موقع آپلود اتفاق می‌افته، مشکلی برای جستجوهای بعدی نیست (اونا از کش حافظه سریع جواب می‌گیرن).
- ستون‌هایی مثل «کد کالا»، «بارکد» و «شماره اموال» عمداً به‌عنوان کد فروشگاه انتخاب نمی‌شن.
